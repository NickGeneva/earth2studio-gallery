# Authoring examples

Examples follow the same numbered-directory style used by Earth2Studio:

```text
docs/examples/
├── 01_getting_started/
│   ├── 01_minimal_image.py
│   └── 02_console_output.py
└── 02_plotting/
    └── 01_sine_wave.py
```

Each script is regular runnable Python in
[Jupytext percent format](https://jupytext.readthedocs.io/en/latest/formats-scripts.html#the-percent-format):

````python
# %%
"""
My Example
==========

A one-paragraph summary used on the gallery card.
"""

# /// script
# dependencies = [
#   "earth2studio-gallery @ git+https://github.com/NickGeneva/earth2studio-gallery.git",
# ]
# ///

# %%
# Create an artifact
# ------------------

# %%
from PIL import Image

Image.new("RGB", (640, 360), "navy").save("example.png")
````

The opening docstring becomes the title and introduction. Comment-only cells become
Markdown, code cells become highlighted Python, printed text becomes an output block,
and created images appear after the cell that produced them.

## Python API cross-references

Sphinx-style Python roles in narrative cells are converted to
[mkdocstrings cross-references](https://mkdocstrings.github.io/usage/#cross-references).
This lets an example refer to an API object by its dotted Python name without knowing which
API page contains it:

```python
# Use :py:class:`earth2studio.models.px.FCN` with
# :py:func:`~earth2studio.run.deterministic`.
# See :py:meth:`the fetch method <earth2studio.data.DataSource.__getitem__>`.
```

The first reference displays the full name, the leading `~` displays only
`deterministic`, and the third uses a custom label. The generated Markdown targets are,
respectively, ``[`earth2studio.models.px.FCN`][earth2studio.models.px.FCN]``,
``[`deterministic`][earth2studio.run.deterministic]``, and
``[`the fetch method`][earth2studio.data.DataSource.__getitem__]``.

Native MkDocs/autorefs links can be authored directly and are equivalent:

```python
# Use [`FCN`][earth2studio.models.px.FCN] with
# [earth2studio.run.deterministic][].
```

When `backreferences = true`, these explicit narrative links also create the reverse
index used by API pages. Imports, calls, annotations, and other Python code are deliberately
not inspected. Add one canonical marker after the corresponding `mkdocstrings` object:

```markdown
::: earth2studio.run.deterministic

<!-- e2sg-backreferences: earth2studio.run.deterministic -->
```

`build` and `render` replace the marker's managed content with the same Material gallery
cards used by the main index. The full index is also saved as
`.e2sgallery/backreferences.json`. Every example source is scanned during a selected build,
so rebuilding one example does not drop references from examples that were not executed.
References whose targets have local markers are written as ordinary relative Markdown links,
so they work in Zensical without a runtime plugin hook.

Generate the API Markdown and its markers before running the gallery command. For Zensical,
enable the feature in the project configuration:

```toml
[tool.earth2studio-gallery]
backreferences = true
```

Install and configure `mkdocstrings-python` in the documentation project so those targets
resolve to the API pages generated by `:::` directives:

```console
uv add --dev mkdocstrings-python
```

```yaml
plugins:
  - search
  - mkdocstrings:
      handlers:
        python:
          paths: [src]
  - earth2studio-gallery:
      examples_dir: examples
      backreferences: true
```

For objects documented on another site, add its Sphinx-compatible `objects.inv` URL under
`handlers.python.inventories`. Both MkDocs and Zensical use this configuration. An unknown
target remains readable inline and is reported during the documentation build instead of
silently linking to the wrong page.

Each generated page offers two downloads by default: the unchanged Jupytext Python
source and a Jupyter notebook. The notebook contains the converted Markdown and code
cells, PEP 723 environment metadata, captured console streams, and embedded original
images, so it opens with the documented outputs already present.

## Custom execution settings

Place `_gallery.toml` in a section to configure all examples below it:

```toml
[runner]
timeout = 14400

[runner.env]
CUDA_VISIBLE_DEVICES = "0"
EARTH2STUDIO_CACHE = "/scratch/earth2studio"
```

Use `01_example.gallery.toml` beside `01_example.py` for a one-example override.
